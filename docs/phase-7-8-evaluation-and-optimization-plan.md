# Phase 7.8 调研评估与优化方案

更新日期：2026-05-16

## 1. 本轮评估范围

本轮不直接改代码，先按固定工作流完成评估。

评估对象包括：

1. `Article` 长文为什么没有正确加一
2. `popup` 哪些内容该保留，哪些内容该降级或移除
3. 每日复盘是否真的有存在价值
4. 执行强度和每日数量的默认数字是否合理
5. 人设叠加到底影响什么，是否需要显性说明

本轮评估依据有两类：

1. 前面已经确认过的产品与方法论文档
2. 当前插件真实界面和现有实现逻辑

---

## 2. 本轮先给结论

### 2.1 `Article` 没有加一，不是产品定义问题，是识别链路还没对上真实发布路径

当前产品定义已经收成了：

- `Article` 才算长文
- 明确线程才算线程
- 其他原创内容算短内容

这个方向是对的，不需要推翻。

现在真正的问题是：

- 你发真实 `Article` 时，插件没有稳定命中那条真实请求
- 所以不是“规则错了”，而是“真实发布链路还没补准”

这件事属于实现问题，不属于产品策略问题。

### 2.2 `popup` 现在还是太满，应该继续瘦身

当前 `popup` 里最不该继续保留的，是：

- 今日任务
- 过重的粉丝编辑交互
- 过早暴露、但还不够智能的内容建议卡片

我建议 `popup` 改成真正的“概览与决策入口”，不再承担执行打卡本身。

### 2.3 每日复盘有产品价值，但当前呈现方式不够成熟

前面的方法论和指标设计都明确强调：

- 每周复盘必须保留
- 每日记录和每日小复盘可以作为周复盘的输入

所以“复盘”本身不该删。

但当前 `popup` 里的每日复盘：

- 让你填最佳帖子 URL、最佳回复 URL
- 但复制时又没有把这些东西真正整合进产出

这就会让用户觉得：

- 我填了，但下游没有用起来

所以问题不在“复盘该不该有”，而在“当前这版复盘先收得太重，兑现得太弱”。

### 2.4 执行强度的默认数字现在不够合理

按前面的调研资料看：

- 当前部分日目标偏低
- `长文 = 每天 1 条` 这类目标又偏重

它的问题不是单纯“多一点还是少一点”，而是：

- **日目标和周目标混在一起了**

更合理的做法不是继续微调单个数字，而是重新把任务拆成：

- 日常动作
- 周深度动作

### 2.5 人设叠加有价值，但现在解释不够

人设叠加不是没用。

它当前实际已经影响：

- 搜索模板关键词
- 内容建议主题
- 每日复盘建议文案
- 候选账号建议判断

但界面里没有把这件事讲清楚，所以用户容易感觉：

- 我选了这个，到底改变了什么

这属于说明缺失，不是功能无效。

## 3. 详细评估

## 3.1 `Article` 长文为什么没加一

### 3.1.1 当前规则本身已经收对了

当前产品口径建议继续保持：

- `Article` -> 长文
- 明确线程 -> 线程
- 其他原创 -> 短内容

这个口径对用户最直观，也最稳定。

### 3.1.2 当前真正的风险点

当前更像是：

- 我们在页面桥接层里监听了“应该会出现”的请求
- 但真实 `Article` 发布时，X 实际走的请求名、路径或页面上下文，没有被这条监听链完整命中

所以现象才会是：

- 短推误判问题已经缓解
- 但真实 `Article` 仍然没有加数

### 3.1.3 本轮产品建议

这一项不需要改产品定义，只需要在后续实现里补两件事：

1. 真实抓一次 `Article` 发布路径
2. 只把真实命中的 `Article` 发布事件计入长文

### 3.1.4 本轮结论

- **长文继续只认 `Article`**
- **实现层需要补真实 Article 发布链路**

---

## 3.2 `popup` 该保留什么

### 3.2.1 目前 `popup` 的问题

当前 `popup` 还混了三种职责：

1. 今日概览
2. 任务执行
3. 复盘录入

这会导致它又像概览页，又像任务页，又像小表单页。

### 3.2.2 建议保留的内容

我建议保留这些：

1. 今日总览
2. 粉丝快照
3. 建议互动
4. 搜索入口
5. 每日复盘入口

### 3.2.3 建议移出 `popup` 的内容

#### A. 今日任务

你提得对，这块现在已经没有必要继续放在 `popup` 里了。

原因很直接：

- 悬浮面板已经承担了今天执行和打卡
- `popup` 再放一份，会重复
- 而且会把 `popup` 挤得很满

本轮建议：

- **从 `popup` 移除今日任务**

#### B. 内容建议卡片

当前内容建议并不是根据实时表现动态算出来的。

它现在本质上是：

- 阶段
- 人设叠加
- 预设话题建议

组合出来的模板型建议。

也就是说：

- 它不是“实时智能建议”
- 它是“结构化提示卡”

所以如果它继续放在 `popup` 里，还占这么高位置，会有两个问题：

1. 用户会误以为它很智能
2. 但实际上它现在还没到这个程度

本轮建议二选一：

1. 从 `popup` 暂时移除
2. 或降级成一行轻量“今日选题提示”

我更推荐第一种：

- **先从 `popup` 移除**
- 等它以后真正能结合历史表现再回来

### 3.2.4 粉丝编辑区的问题

当前粉丝卡片下方那个输入 + 保存交互，确实偏重，也不够好看。

我建议改成：

- 默认只显示今日粉丝和较昨日变化
- 下面放一个很轻的 `手动修正` 按钮或文字入口
- 点击后再展开输入框

这样更符合极简入口的定位。

### 3.2.5 建议互动和搜索入口应该“展示更完整”

这点我认同。

当前如果只显示过少条目，用户会觉得信息不够用。

本轮建议：

- 建议互动默认展示 `3-4` 条
- 搜索入口默认展示 `3-4` 条

但仍然保持单行式和紧凑样式，不做大块卡片。

### 3.2.6 本轮结论

`popup` 应该收成：

1. 今日总览
2. 粉丝快照
3. 建议互动
4. 搜索入口
5. 每日复盘入口

同时：

- 移除今日任务
- 下调或移除内容建议
- 粉丝编辑改成轻量展开式

## 3.3 每日复盘到底有没有必要

### 3.3.1 从前期资料看，它是有必要的

前面的资料其实已经给了很明确的答案。

#### 在方法论文档里

已经明确强调：

- 每周复盘是必须保留的
- 如果不复盘，就不知道什么有效、什么无效

#### 在指标设计里

也明确保留了：

- 周复盘
- 最佳内容
- 最佳回复
- 模式判断
- 下周动作

所以从产品主线看：

- **复盘必须保留**

### 3.3.2 当前真正的问题

当前每日复盘之所以让你觉得别扭，不是因为它没价值，而是因为：

1. 你填了 `最佳帖子 URL / 最佳回复 URL`
2. 但这些数据没有被很好地“用起来”
3. `复制复盘` 的结果也没把这些链接带出去

这就导致：

- 用户感受不到投入和回报

### 3.3.3 这块应该怎么收

我建议分两层：

#### A. 每日复盘保留，但降成轻量版

`popup` 里只保留：

- 今日一句总结
- 明日一个动作
- 一个复制草稿按钮

#### B. 最佳链接改成“补充素材”

`最佳帖子 URL / 最佳回复 URL / 最佳帖子形态`

不要再当成 `popup` 主界面里的默认强填写项。

建议改成：

- 折叠区
- 或单独的“补充素材”区域

这样只有愿意认真记录的人才会继续填。

### 3.3.4 如果保留这些链接，后面必须兑现

如果后面还要保留这些字段，那就必须在后续周复盘里真正用起来，比如：

- 本周最佳带粉帖
- 本周最佳回复
- 本周最值得复刻的表达形式

否则它们继续留在当前界面里，意义会越来越弱。

### 3.3.5 本轮结论

- **每日复盘有必要保留**
- **但要改成轻量版**
- **最佳 URL 字段不能再放成当前这种重表单**

## 3.4 执行强度与每日数量：当前数字是否合理

### 3.4.1 当前最明显的问题

当前任务模板里，至少有两个方向不合理：

#### A. 回复类任务部分偏低

前期调研资料已经建议：

- 保守：`5`
- 标准：`8-10`
- 强执行：`12-15`

这是对“高质量互动”更稳的区间判断。

#### B. 长文按“每天 1 条”不合理

这和前面的阶段打法不一致。

因为前面的资料强调的是：

- 高价值主内容按周节奏安排
- 每周 `2-4` 条
- 每周再做 `1-2` 条结果复盘内容

这意味着：

- 长文或深内容更适合周级安排
- 不适合直接硬塞进每个阶段的日目标

### 3.4.2 当前最大结构问题

不是数字本身，而是：

- **把日常动作**
- 和 **深度内容动作**
- 放进了同一个“每日数量”里

这会让：

- 短内容看起来偏少
- 长文看起来偏重

### 3.4.3 本轮建议

建议把强度重新理解成两层：

#### A. 日常动作强度

更适合做日目标的：

- 短内容
- 高质量回复
- 大 V 互动
- 同生态互动
- 选题收集
- 当日复盘

#### B. 深度内容强度

更适合做周目标的：

- 长文
- 高价值主帖
- 对标拆解
- 周复盘

### 3.4.4 是否支持“自定义保守 / 标准 / 强执行”

这是一个合理方向。

但我不建议这轮就先做完整的“用户自定义三套模板”。

原因是：

- 这会把当前改造范围一下拉大
- 现在更应该先把默认内置数字调合理
- 再在下一轮增强时支持“保存为我的保守 / 标准 / 强执行”

### 3.4.5 本轮建议结论

本轮先做：

1. 重新校正内置数字
2. 把深度内容从“日目标”里降权
3. 优先让默认预设更符合之前调研

后续增强版再考虑：

- 自定义保存为我的保守 / 标准 / 强执行

---

## 3.5 人设叠加：到底影响什么

### 3.5.1 当前真实作用

人设叠加现在实际已经影响了：

1. 搜索模板关键词
2. 内容建议主题
3. 每日复盘建议的补充文案
4. 候选账号的关键词匹配判断

### 3.5.2 为什么用户感知还是弱

因为当前界面没有把这件事直接说清楚。

用户会知道：

- 我可以选人设

但不知道：

- 选完后，具体哪里会变化

### 3.5.3 本轮建议

在人设叠加区域加一段很短的说明：

例如：

`它会影响搜索模板、内容建议、复盘建议，以及候选账号的关键词判断。`

这句话就够了，不需要写长篇说明。

### 3.5.4 本轮结论

- 人设叠加应该保留
- 需要加一句非常明确的作用说明

## 6. 本轮实施建议顺序

如果你确认进入下一轮实现，我建议顺序固定成这样：

1. 先修 `Article` 长文识别
2. 再收 `popup`
3. 再重调执行强度默认数字
4. 再收每日复盘的轻量化
5. 最后补人设叠加说明

这个顺序最稳，因为它先解决：

- 记录准不准
- 入口重不重
- 预设值合不合理
