# Phase 7.5 修正版实施方案

更新日期：2026-05-15

## 1. 文档目的

这份文档用于收敛 `Phase 7.5` 的修正版范围，重点解决当前版本已经暴露出来的 4 类问题：

1. `X` 页面悬浮轻面板没有稳定显示
2. 执行强度与每日数量设置过于拥挤，理解成本高
3. 候选处理 / 正式账号池的操作路径过重，不像成熟产品
4. 中文搜索模板没有真正贴合简体中文区 `X` 使用场景

本次修正版目标不是增加更多大模块，而是把现有能力真正做顺、做稳、做得像产品。

---

## 2. 当前问题归纳

### 2.1 悬浮轻面板问题

当前问题：

- 用户在真实 `X` 页面中没有稳定看到悬浮轻面板
- 轻面板当前是“拿到全部数据后一次性渲染”，容错不够
- 一旦数据读取、页面挂载或路由切换有异常，用户看起来就是“完全没显示”

这会直接影响插件的存在感。  
如果用户必须每次点扩展图标，插件就仍然像一个后台工具，而不是执行助手。

### 2.2 执行强度设置问题

当前问题：

- `保守 / 标准 / 强执行` 三套说明和自定义任务数量同时展开，界面过挤
- 用户很难理解“预设”和“手动改目标”之间的关系
- 虽然已经支持即时重建今天任务目标，但在界面上不够自然

这会让用户觉得“设置复杂、看不懂、调起来麻烦”。

### 2.3 候选处理 / 正式账号池问题

当前问题：

- 候选页和正式账号池虽然已经拆分，但操作仍然偏重
- 自动建议结果过于偏向 `对标学习`
- 建议标签和最终标签绑得太紧，用户修改分类要绕路
- 筛选区仍然偏表单思维，不像成熟列表产品
- 卡片的交互粒度不合理，很多操作本来应该在卡片上直接完成

这会让用户不断来回点按钮，感觉自己在“维护表格”，不是在“管理关系”。

### 2.4 中文搜索模板问题

当前问题：

- 模板文案虽已部分中文化，但实际查询逻辑还不够贴合中文区
- 系统模板没有一个明确的“恢复 / 重新生成”动作
- 用户本地旧模板可能仍在，导致“你说改了，但我看到的没变”

这会让搜索模板失去作为“任务入口”的价值。

---

## 3. 修正版目标

本次修正版只做 4 件事：

1. 让悬浮轻面板稳定可见
2. 把执行强度改成一个清晰、可调、即时生效的统一面板
3. 把候选处理 / 正式账号池收成更成熟的账号工作台
4. 把中文搜索模板真正改成适合简体中文区的默认系统模板

---

## 4. 产品设计原则

### 4.1 原则一：平时直接操作，批量时再显式进入批量模式

单个账号最常见的动作应该是“直接点一下就改”。  
只有当用户主动勾选多个对象时，才出现批量操作条。

### 4.2 原则二：建议是建议，分类是分类

系统可以给出建议，但不能让建议结果直接等于最终结果。

用户应始终能快速改成：

- 同生态
- 对标学习
- 选题来源
- 待判断

### 4.3 原则三：执行设置必须一眼看懂

用户只需要理解两件事：

1. 我现在选的是哪种强度
2. 今天每项任务到底要做多少

不应该让用户先读三段说明，再去下面理解自定义逻辑。

### 4.4 原则四：轻面板只做执行入口，不做详情后台

悬浮轻面板只负责：

- 看进度
- 快速打卡
- 快速打开设置或详情

详细信息仍然交给 `popup` 和 `options`。

---

## 5. 外部参考方向

本次修正版不再靠主观想象，会有意识地借成熟产品的交互模式。

### 5.1 候选处理 / 正式账号池

参考方向：

- `Apollo`
  - 适合借“筛选 -> 勾选 -> 批量动作”的列表管理方式
- `Linear`
  - 适合借更克制、更轻量的顶部过滤条
- `Airtable`
  - 适合借“同一份数据，不同视图”的思路

本项目不会照搬视觉样式，但会借它们的交互结构。

### 5.2 悬浮面板 / 页面内助手

参考方向：

- `StreakX`
  - 适合借“轻量进度感”
- `SuperX`
  - 适合借“内嵌在 X 页面里的增长视图”
- `BlackMagic`
  - 适合借“贴着账号关系管理”的思路

## 6. 修正版实施范围

## 6.1 修正包 A：悬浮轻面板稳定化

### 目标

让用户在真实 `X` 页面稳定看到面板，而不是“有时代码有、页面没显示”。

### 调整方案

1. 改成“先渲染空壳，再补数据”
   - 页面加载后先出现面板骨架
   - 数据异步补进来
   - 不再等所有数据拿齐后才整块渲染

2. 增加可见降级状态
   - 即使数据没准备好，也至少显示：
     - 插件标题
     - 加载中
     - 打开设置

3. 强化路由切换重挂载
   - `X` 单页路由变化后，轻面板应自动检查并补挂

4. 增加显式开关状态提示
   - 如果用户在设置里关闭轻面板，应明确不显示
   - 如果开启，应有最小可见状态

### 交付结果

- 在 `x.com/home`
- 在 `x.com/<handle>`
- 在路由切换后

都能稳定看到轻面板

### 验收标准

1. 打开任意 `X` 页面，右上角出现轻面板
2. 即使数据未完全加载，轻面板也至少显示空壳
3. 切换页面路径后，轻面板不会消失
4. 关闭该开关后，轻面板应立即隐藏

---

## 6.2 修正包 B：执行强度面板重构

### 目标

把“预设 + 自定义”收成一个清楚的统一面板。

### 调整方案

改成 4 档：

- `保守`
- `标准`
- `强执行`
- `自定义`

### 交互逻辑

1. 用户点击 `保守 / 标准 / 强执行`
   - 下方任务目标自动填充

2. 用户手动修改任意任务目标
   - 当前档位自动切换为 `自定义`

3. 保存后
   - 立即重建今天任务目标
   - 保留今天已经完成的进度
   - 只改变目标上限和完成率计算

### 页面结构

顶部：

- 当前阶段
- 执行强度切换

中部：

- 每日任务目标列表
  - 任务名
  - 当前目标值
  - 数字输入框

底部：

- 保存并重建今天任务
- 生效说明

### 验收标准

1. 用户一眼能看出当前档位
2. 用户一改某项任务目标，档位自动变成 `自定义`
3. 保存后 `popup` 和轻面板能看到新目标
4. 已完成的任务进度不被清零

---

## 6.3 修正包 C：账号工作台重构

### 总体方向

不再让候选页和正式账号页像两张独立表单，而是做成更成熟的工作流：

- 候选页：重在判断和决策
- 正式页：重在维护和跟进

### 6.3.1 候选处理页

#### 目标

让用户可以在卡片上直接做最常用的标签操作。

#### 主要调整

1. 筛选区重做

改成两行：

第一行：

- 搜索框
- 状态切换

第二行：

- 来源筛选
- 建议标签筛选
- 置信度筛选（可选）

2. 卡片标签直接可改

卡片上不再只是展示标签，而是直接提供一个角色下拉：

- 同生态
- 对标学习
- 选题来源
- 待判断

用户点一下就能改，不必先勾选、再找批量按钮。

3. 自动建议降级为“建议值”

卡片上显示：

- 建议标签
- 当前标签

如果用户没改，就用建议值  
如果用户改了，就以后者为准

4. 批量操作改成“勾选后浮出”

只有在用户勾选多个账号后，才出现：

- 批量加入正式账号池
- 批量改角色
- 批量忽略
- 批量恢复待处理

#### 自动建议逻辑修正

建议顺序改成：

1. 明显信息源 / 复盘 / 趋势账号  
   -> `选题来源`

2. 明显命中当前人设关键词、赛道关键词  
   -> `同生态`

3. 量级明显更高、且不属于前两类  
   -> `对标学习`

4. 判断不稳  
   -> `待判断`

这样可以避免“几乎全变成对标学习”。

### 6.3.2 正式账号池页

#### 目标

让已入池账号的维护变简单，而不是只能看、只能删。

#### 主要调整

1. 顶部筛选更轻

- 搜索
- 角色筛选
- 粉丝量级筛选

2. 卡片正面只保留高价值信息

- 名称
- handle
- 角色标签
- 粉丝量级标签
- 优先级
- 最近互动时间
- 简短备注

3. 卡片内直接可改

- 角色标签下拉
- 粉丝量级下拉
- 打回待处理
- 移到已忽略
- 删除

4. 分页或折叠必须保留

后期账号一定会越来越多，不能默认无限下拉。

### 验收标准

1. 用户能在候选卡片上直接改角色标签
2. 自动建议不再大面积偏向 `对标学习`
3. 多选后才出现批量操作条
4. 正式账号页支持分页
5. 正式账号卡片支持直接维护

---

## 6.4 修正包 D：中文搜索模板重建

### 目标

让系统模板真正适合简体中文区，而不是“看起来是中文，实际逻辑不对”。

### 主要调整

1. 增加两个显式动作

- `恢复系统模板`
- `按当前人设重新生成系统模板`

2. 固定一套中文默认模板

建议保留这 6 个：

- 中文问题帖
- 中文爆款复盘
- 中文创作者最近在聊什么
- 中文实时新帖
- 中文低粉优质账号
- 中文选题来源

3. 系统模板与用户自建模板分层

- 系统模板：可重建、可恢复
- 用户模板：永远不被覆盖

4. 人设叠加真正进入模板生成

例如：

- 选了 `AI Creator`
  - 更偏 `AI / 自动化 / 工作流`
- 选了 `Indie Hacker`
  - 更偏 `独立开发 / 产品 / 增长 / 用户反馈`

### 验收标准

1. 用户能一键恢复系统模板
2. 用户能一键按当前人设刷新系统模板
3. 默认模板全部是简体中文区可用逻辑
4. 用户自己的模板不会被覆盖

## 7. 页面信息架构调整

修正版仍保留 3 个一级页：

1. `执行设置`
2. `候选处理`
3. `正式账号池`

但每页职责要更纯：

### 执行设置

- 阶段
- 强度
- 自定义每日目标
- 人设叠加
- 系统搜索模板

### 候选处理

- 自动导入提醒
- 待处理候选账号
- 标签判断
- 批量决策

### 正式账号池

- 长期跟进对象
- 标签维护
- 量级维护
- 优先级维护

---

## 8. 实施顺序

为了避免再次“改一大块，结果问题还没压住”，建议按下面顺序实施：

### 第一步

修正包 A：悬浮轻面板稳定化

原因：

- 这是用户感知最直接的问题
- 不显示，其他再好也没有存在感

### 第二步

修正包 B：执行强度面板重构

原因：

- 这是用户每天都会碰到的设置入口
- 必须先做到直观

### 第三步

修正包 C：账号工作台重构

原因：

- 当前这块最影响“它像不像产品”
- 也是最容易反复调整的部分

### 第四步

修正包 D：中文搜索模板重建

原因：

- 这块逻辑清楚后，后面的内容建议和搜索入口才会真正好用

---

## 9. 不在本次修正版内的内容

本次修正版明确不做：

- 新增新的大阶段模块
- 新增自动发帖
- 新增自动评论
- 新增复杂 AI 分类引擎
- 新增大规模关系图谱分析
- 新增完整周报 / 月报分析后台

这些会分散当前重点。

---

## 10. 审核重点

你审核这份方案时，重点只需要看 6 件事：

1. 是否确认执行强度改成 `保守 / 标准 / 强执行 / 自定义`
2. 是否确认候选卡片标签要支持直接改，不再只靠批量按钮
3. 是否确认自动建议应降级为“建议值”，不再直接当最终标签
4. 是否确认正式账号页应重点做维护，而不是再走导入逻辑
5. 是否确认中文系统模板要支持“恢复”和“按当前人设重建”
6. 是否确认本轮优先级先修悬浮轻面板，再修执行设置，再重做账号工作台

---

## 11. 结论

`Phase 7.5` 修正版的目标不是“功能更多”，而是：

- 让轻面板稳定出现
- 让设置真正容易理解
- 让账号工作台更像成熟产品
- 让搜索模板真正适合中文区

如果这版审核通过，下一步开发就按这 4 个修正包顺序推进，不再继续横向扩张功能。
