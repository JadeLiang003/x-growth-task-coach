# Phase 8 实施计划：视觉收口、导出接线与交付收尾

## 1. 当前判断

`Phase 8` 现在不应该继续无边界扩功能，而应该拆成两段：

1. **先把 Phase 8A 的视觉语言收干净**
2. **再进入 Phase 8B 的导出接线**

原因很简单：

- 当前热力图和粉丝趋势已经具备功能基础
- 但界面层级、留白、按钮权重和时间语义还没有完全稳定
- 如果现在直接往下加导出，很容易把设置页再次做重

所以这一轮的正确顺序不是“继续塞新模块”，而是：

> 先把现有执行与趋势区做成稳定成品，再接导出能力。

---

## 2. 本阶段的工作边界

### 2.1 一定要做

1. 继续收口热力图与粉丝趋势区的视觉结构
2. 给 `Phase 8B` 导出接线定清楚入口、范围和按钮层级
3. 完成导出能力的轻量接线
4. 最后做一次统一测试和文档收尾

### 2.2 这一阶段不做

1. 不新增一级页面
2. 不新增新的分析模式
3. 不做云同步
4. 不做导入回写
5. 不做复杂导出向导
6. 不把 `popup` 再做成小后台

这条边界必须固定：

> 如无必要，勿增实体。

---

## 3. 产品经理复审结论

## 3.1 入口必须继续收敛

当前插件已经有三个稳定入口：

- 悬浮窗
- `popup`
- 设置工作台

`Phase 8` 的新增内容只能挂在这三个入口下：

- 悬浮窗：不加热力图、不加导出
- `popup`：只放轻量概览
- 设置工作台：放完整视图和导出入口

这意味着：

- 热力图完整版本只能留在设置页
- 导出入口只能放在设置页
- `popup` 只能保留轻量概览能力

---

## 3.2 当前 8A 需要先收口的地方

结合当前界面截图、现有实现和 `DESIGN.md`，现在有 4 个地方必须收紧：

### 1. `popup` 热力图

当前问题：

- 视觉重心仍然偏左
- 格子尺寸和间距还不够精细
- 时间信息不够“像一个完整的时间视图”

产品判断：

- `popup` 应该继续保留 **近 90 天 / 3 个月**
- 但它应该像一个完整小部件，不像一个临时拼出来的图块

### 2. 设置页热力图

当前问题：

- 单块虽然已横向展开，但顶部信息和主体之间仍然有割裂感
- 统计区与热力图区的关系还不够自然
- 热力图已经更接近 GitHub 语义，但还需要更明确地成为“主内容”

产品判断：

- 设置页热力图应继续保留 **近一年 GitHub 风格横向视图**
- 不回退成单月切换版
- 因为一年视图更适合长期执行工具，也更能撑起左侧主要版面

### 3. 粉丝趋势区

当前问题：

- 按钮与数据层级偶尔仍然抢主信息
- 卡片视觉权重略重

产品判断：

- 粉丝趋势仍应保留在右侧
- 但它的职责只是“结果趋势补充”，不能抢热力图的主角位置

### 4. 按钮与副标题

当前问题：

- 局部按钮仍偏大
- 一些副标题和说明文案偏啰嗦

产品判断：

- 所有辅助说明继续删减
- 只保留真正帮助理解的最短文案
- 状态、说明、成功提示优先收进按钮自身，不单独做重块

  - 用于 `popup` 里轻量折叠区和概览区的克制层级

## 4.2 热力图视觉原则

### popup

必须做到：

- 格子更小
- 间距更紧
- 三个月排布更均衡
- 月份标签与图本体保持一体化
- 不做大段解释
- 不让图靠左缩成一团

### 设置页

必须做到：

- 年视图作为左侧主内容，宽度吃满
- 月份标签在上
- 星期刻度在左
- 统计区成为热力图的自然延伸，而不是三张独立小卡片堆在下面

也就是说：

> 设置页应该像“执行时间密度主图 + 右侧结果趋势补图”。

---

## 4.3 粉丝趋势视觉原则

### popup

- 保留粉丝数主数字
- 保留较昨日增减
- 保留轻量 sparkline
- `手动修正` 必须继续压轻
- 它只能是辅助动作，不是主 CTA

### 设置页

- 趋势图区应更像“结果摘要卡”
- 先展示当前粉丝与增减
- 再展示趋势
- 不要在一张卡里放太多说明文字

## 5. Phase 8A 收口后的最终结构

## 5.1 popup

顺序固定为：

1. 今日总览
2. 执行热力图（近 90 天 / 3 个月）
3. 粉丝快照 + 趋势
4. 建议互动
5. 搜索入口
6. 每日复盘

### 建议互动

固定成：

- 每个推荐账号占一行
- 一行只保留：
  - 名字
  - `@handle`
  - 一个角色标签
  - 必要时一个量级标签

### 搜索入口

固定成：

- 点击标题
- 一层展开 / 收起全部 4 个入口

### 每日复盘

固定成：

- 正文
- 复制按钮
- `附录`

不再补回重复标签。

---

## 5.2 设置页

这一块固定成左右双栏：

### 左侧：执行热力图

- 标题：`近一年执行热力图`
- 主体：GitHub 风格年视图
- 底部：轻量统计

### 右侧：粉丝趋势

- 当前粉丝
- 较昨日增减
- 近 30 天趋势线

这两块应该形成：

> 左边看执行，右边看结果。

## 6. Phase 8B：导出接线的产品方案

## 6.1 它是什么

`Phase 8B` 不是再做一个“导出系统”，而是把现在已经积累在插件本地的数据，接成用户可以直接下载的按钮。

它的目标是：

- 备份
- 迁移
- 自己分析
- 做长期复盘

---

## 6.2 入口放在哪里

只放在：

- **设置页底部**

形式：

- 一个折叠区
- 标题：`数据与导出`

不放在：

- `popup`
- 悬浮窗
- 新 tab

---

## 6.3 导出范围

第一版只做 5 个动作：

1. 完整备份 `JSON`
2. 每日记录 `CSV`
3. 粉丝快照 `CSV`
4. 账号工作台 `CSV`
5. 每日复盘 `CSV`

不做：

- 字段勾选
- 高级筛选
- 文件名配置
- 导出模板

---

## 6.4 导出按钮的交互原则

必须遵守：

1. 低频动作不抢主视觉
2. 一个按钮做一件事
3. 不做导出向导
4. 成功与失败尽量通过按钮状态反馈
5. 不新增大面积提示块

推荐结构：

- 区块标题
- 一句很短的说明
- 一组轻按钮

## 9. 验收标准

这一轮完成后，至少满足：

1. `popup` 热力图不再左缩、视觉重心均衡

4. 次级按钮不再视觉过重

6. 5 个导出按钮都能正常下载
7. 不新增一级页面
8. 不新增复杂模式
9. 不把 `popup` 做重
