# Phase 7.6 界面重构审核包

更新日期：2026-05-15

## 1. 这轮审核包的目标

这轮不是继续零碎修小问题，而是按固定工作流，先把当前插件界面重构所需的内容一次性收口。

本轮只做一件事：

**把“悬浮框 + popup + 设置工作台”收成一套统一、克制、成熟的工具界面。**

---

## 2. 当前真实问题

结合你最近多轮反馈，当前问题已经很明确了。

### 2.1 悬浮框问题

- 展开态和收起态都偏宽
- 收起态虽然已经能用，但还不够短
- 收起态信息还可以更克制
- 标题还需要进一步固定成正式产品感

### 2.2 popup 问题

- 仍然不够极简
- 还有多余信息块
- 还不像一个真正的轻入口

### 2.3 设置工作台问题

- 执行强度与每日数量仍然太重、太啰嗦
- 输入项和单位对齐不够好
- 有重复说明文案
- 候选处理和正式账号池仍然像两个割裂后台
- 标签操作还不够直接

### 2.4 角色标签问题

- 角色标签太细会增加理解成本
- `选题来源` 作为主标签价值不够高
- 用户真实更容易接受的是：
  - `同生态`
  - `对标学习`

---

## 2.5 需求优先级归类

### 必须做

- 悬浮框进一步收窄
- 收起态更短、信息更克制
- popup 极简化
- 执行强度与每日数量重构
- 候选处理 / 正式账号池统一成一个账号工作台
- 标签操作改成更直接的轻交互

### 应该做

- 人设叠加区进一步压缩说明文案
- 账号卡片信息层级继续收紧
- 批量操作条继续做轻

### 可延期

- 搜索模板进一步细化
- 更复杂的账号推荐逻辑
- 更多个性化配置

### 不做

- 新增大模块
- 新增分析页
- 新增更多角色标签

## 3. 这轮产品判断

### 3.1 popup 要不要取消

**结论：不取消。**

原因：

- 浏览器扩展本来就需要一个轻入口
- 不是所有页面都适合只靠悬浮框
- 设置工作台不适合承担“快速看一眼”的职责

因此：

- 悬浮框：执行中一直看
- popup：快速总览和入口
- 设置工作台：重管理、重编辑

### 3.2 候选处理和正式账号池要不要合并

**结论：数据层不硬合并，界面层合并成统一账号工作台。**

原因：

- 候选和正式账号本身状态不同，数据不应强行混在一起
- 但用户不需要在两个完全割裂的页面里来回跳

因此：

统一做成一个“账号工作台”，顶部切换：

- `待处理`
- `已入池`
- `已忽略`

### 3.3 选题来源要不要保留

**结论：不再作为主标签保留。**

原因：

- 理解成本高
- 命中率低
- 产品收益不够大

因此主标签收成：

- `同生态`
- `对标学习`

### 3.4 这轮是否继续加新功能

**结论：不加新功能。**

本轮只做界面和交互重构，不再扩展新模块。

## 4. 设计基线

### 4.1 总风格主参考

- **整体界面：Linear**

目标：

- 克制
- 清楚
- 信息密度高但不乱
- 没有后台模板味

### 4.2 轻面板与 popup 参考

- **Raycast**

目标：

- 快
- 轻
- 干净
- 不啰嗦

### 4.3 列表、标签、批量操作参考

- **GitHub Issues**

目标：

- 标签直接可操作
- 勾选后再出现批量条
- 不做一堆大块控制区

### 4.4 设置工作台的克制感补充参考

- **Vercel Dashboard**

目标：

- 后台工具感强
- 控件轻
- 文案少
- 页面层次安静

## 5. 页面级重构方案

## 5.1 悬浮框

### 保留

- 继续保留悬浮框
- 继续保留拖动
- 继续保留全部任务
- 继续保留细进度条

### 删除

- 删除空话型文案
- 删除不必要的大按钮感

### 新结构

展开态：

- 标题：`X 增长插件`
- 副标题：`今日打卡`
- 一条总进度条
- 全部任务列表
- 底部轻量统计

收起态：

- 更短
- 显示：
  - 百分比
  - `今日进度`
  - 一条细进度条
- 收起态继续可拖动

### 实施要求

- 整体宽度再收窄
- 收起态宽度进一步压缩
- 设置入口必须稳定打开设置页

## 5.2 popup

### 保留

- 今日总览
- 粉丝快照
- 今日任务
- 建议互动
- 搜索入口
- 内容建议
- 每日复盘

### 删除

- 调试性质的信息
- 冗余状态块
- 解释型废话
- 第二后台式堆砌

### 目标

打开后 2 到 3 秒内扫完，不需要阅读说明。

## 5.3 设置工作台

### 保留

- 执行强度与每日数量
- 人设叠加
- 搜索模板
- 账号工作台

### 重构重点

#### A. 执行强度与每日数量

改成左右双栏中的左栏。

结构：

- 顶部一排预设：
  - `保守`
  - `标准`
  - `强执行`
  - `自定义`
- 下方紧凑数字列表

交互：

1. 点击预设，数字自动替换
2. 手动改数字，自动进入 `自定义`
3. 不再显示重复说明文案
4. 输入框和单位列必须严格对齐

#### B. 人设叠加

放在右栏。

要求：

- 说明文案压缩
- 模板和自定义保留
- 视觉上不空、不重

#### C. 账号工作台

统一成一个页面，不再做两套割裂逻辑。

顶部视图切换：

- `待处理`
- `已入池`
- `已忽略`

单条账号卡片要求：

- 用户名
- handle
- 主标签紧贴名字
- 粉丝量级标签紧跟主标签
- bio 两行
- 轻量操作

标签操作方式：

- 标签本身就是小下拉
- 不再另做大块“角色标签下拉区”

删除：

- 查看建议理由
- 大状态反馈块
- 又多又重的操作按钮组

## 6. 实施包拆分

## 包 A：结构重构

目标：

- 统一账号工作台
- 收紧 popup
- 收紧悬浮框

包含：

- 悬浮框宽度和收起态重构
- popup 极简化
- 候选处理 / 正式账号池合并成统一视图结构

## 包 B：执行设置重构

目标：

- 让执行强度区一眼看懂

包含：

- 预设切换
- 自定义切换
- 数字输入区重排
- 对齐修正
- 文案删除

## 包 C：标签交互重构

目标：

- 让标签本身成为操作入口

包含：

- 主标签收成两类
- 标签小下拉
- 批量操作条轻量化
- 删除重按钮和冗余说明

## 7. 本轮不做的事

这轮明确不做：

- 新增增长功能
- 新增复杂分析页
- 新增角色标签体系
- 新增搜索模板大改版
- 新增自动化采集链路

本轮就是界面重构。

---

## 8. 验收标准

这轮完成后，至少要满足：

1. 悬浮框展开态和收起态都明显更窄
2. 收起态显示百分比、短文案和细进度条
3. 收起态继续可拖动
4. popup 打开后明显更轻，不再像小后台
5. 执行强度区没有重复废话
6. 执行强度区数字和单位严格对齐
7. 候选处理和正式账号池不再是两套割裂体验
8. 标签本身可以直接改
9. 主标签只保留 `同生态 / 对标学习`
10. 改完后自动化回归通过
