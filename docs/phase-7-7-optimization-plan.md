# Phase 7.7 进一步优化方案

## 1. 目标

这一轮不是继续加新功能，而是把当前插件里最影响使用体验的 3 条链路一次性收顺：

1. 内容识别要更稳，避免短推被误判成长文
2. 执行强度与每日数量要真正好用，不再出现“点了没反应”
3. 账号工作台要保留批量能力，但默认界面更轻、更直接

本轮继续遵循已经确认的工作流：

1. 先评估需求
2. 再做界面与交互收口
3. 再实现
4. 再自动化验证
5. 失败则返修，最多 3 轮

---

## 2. 本轮评估结论

### 2.1 必须修的产品问题

#### A. 短推被误判成长文

当前问题：

- 用户发普通短推并点击 `Post`
- 插件仍可能把它记成 `长文`

判断：

- 这是识别策略过宽，不是用户操作问题
- 当前规则把 `Note`、长文本、请求体中的某些字段都算进了长文
- 对普通用户来说，这套规则不直观，也不稳定

本轮结论：

- `Article` 才算长文
- 明确识别为线程的，才算线程
- 其他原创内容统一按短内容处理

也就是：

- `Article` -> 长文
- `Thread` -> 线程
- 其他原创 `Post` -> 短内容

这是本轮最高优先级修正项。

---

#### B. 执行强度区交互有断层

当前问题：

- 点击 `保守 / 标准 / 强执行` 后，右侧数量输入框没有同步变化
- 用户改了输入框，不知道是否自动保存
- 当前说明文案偏多，但关键反馈不够明确

判断：

- 当前交互不完整
- 预设和自定义没有形成一套连贯流程

本轮结论：

执行强度区需要改成一条完整链路：

1. 点击 `保守 / 标准 / 强执行`
   - 数字立即变化
2. 用户手动改任意一个数量
   - 自动切换成 `自定义`
3. 用户完成输入后
   - 采用 `失焦保存` 或 `短暂停顿后自动保存`
4. 保存完成后
   - 自动重建今天目标
   - 保留今天已完成进度

同时保留一条很短的说明：

- `预设决定默认节奏，改数字后自动进入自定义`

每个任务行支持一个轻量提示：

- 说明该任务的判定方式或目标含义

不再堆大段解释文案。

---

#### C. 账号工作台重复操作太多

当前问题：

- 顶部已有标签筛选
- 中间又有“仅勾同生态 / 仅勾对标学习”
- 勾选后又出现“加入账号池 / 改成同生态 / 改成对标学习”
- 多层逻辑重叠，用户会觉得重复和绕

判断：

- 批量模式有必要保留
- 但不应该默认摊在页面上
- 当前问题不是“要不要批量”，而是“批量模式太早暴露”

本轮结论：

账号工作台采用双模式：

### 默认模式

默认界面只保留：

- 搜索
- 来源筛选
- 标签筛选
- 卡片标签直改
- 单条加入账号池 / 忽略 / 恢复
- 一个入口：`进入批量模式`

默认模式下：

- 不显示复选框
- 不显示批量操作条
- 不显示“仅勾同生态 / 仅勾对标学习”

### 批量模式

进入批量模式后，才显示：

- 复选框
- `全选当前页`
- `全选当前筛选结果`
- `清空`
- `加入账号池`
- `改成同生态`
- `改成对标学习`
- `忽略 / 恢复`
- `退出批量模式`

这样可以兼顾两类用户：

- 轻量用户：默认单条操作即可
- 重度用户：需要批量时再进入批量模式

---

#### D. 手动新增账号不能丢

当前问题：

- 统一工作台后，手动新增账号的能力不应该被削弱

判断：

- 真实使用里，手动补充账号仍然必要

本轮结论：

正式账号区保留一个轻量的手动新增入口：

- 默认收起
- 需要时展开
- 不做成重表单

位置建议：

- 放在 `已入池` 视图下方
- 标题类似 `手动补充账号`

---

## 3. 本轮结构方案

### 3.1 内容识别

重新收成三类：

1. 短内容
2. 线程
3. 长文

识别口径：

- 长文：仅 `Article`
- 线程：仅明确线程发布路径
- 其他原创：全部归到短内容

附加策略：

- 如果识别不确定，不要主动归长文
- 识别失败时默认回退到短内容

---

### 3.2 执行强度与每日数量

界面结构：

- 上方：`保守 / 标准 / 强执行 / 自定义`
- 下方：紧凑任务行列表

任务行结构：

- 左：任务名
- 左下：一句话副标题
- 中：数量输入框
- 右：单位

交互规则：

1. 点击预设
   - 覆盖输入框数值
2. 修改输入框
   - 当前状态切换为 `自定义`
3. 自动保存
   - 触发时机：失焦或短暂停顿
4. 自动重建今天任务
   - 只更新目标上限
   - 保留已完成值

提示规则：

- 顶部保留一行极简说明：
  - `预设决定默认节奏，改数字后自动进入自定义`
- 每个任务行在任务名下方直接显示一句话副标题
- 不再依赖悬浮说明和大段解释文案

副标题的目的只有一个：

- 让用户立刻明白这项任务算什么，以及做到什么程度才算完成

副标题文案要求：

- 只写一句话
- 保持简洁
- 优先解释判定标准
- 不讲空泛方法论

示例方向：

- `短内容输出`：发一条普通短推就计一次，不含 Article。
- `长文`：只有发布 X Article 才计入长文。
- `高质量回复`：回复里要有观点、经验或补充信息，不能只是客套话。
- `大 V 互动`：和高量级目标账号完成一次有效回复或引用互动。
- `同生态互动`：和同赛道账号完成一次真实互动，而不是单纯点赞。
- `选题收集`：记下一条之后可以展开写内容的具体问题、案例或角度。
- `当日复盘`：补齐当天链接或总结，并完成一次简短回看。

最终形态应该是：

- 一行标题
- 一行副标题
- 一个数量输入框

这样既克制，也能让用户快速理解每个标签的含义。

---

### 3.3 账号工作台

继续保留统一工作台结构：

- `待处理`
- `已入池`
- `已忽略`

但进一步拆成：

#### 默认模式

- 搜索
- 来源筛选
- 标签筛选
- 卡片直接改标签
- 单条加入 / 忽略 / 恢复
- `进入批量模式`

#### 批量模式

- 显示复选框
- 顶部显示批量操作条

批量操作条内容：

- 已选数量
- 全选当前页
- 全选当前筛选结果
- 清空
- 加入账号池
- 改成同生态
- 改成对标学习
- 忽略 / 恢复
- 退出批量模式

这样后：

- “筛选”负责缩小范围
- “批量模式”负责大规模操作
- “默认模式”负责轻量管理

---

### 3.4 手动新增账号

恢复到账号工作台中，但保持轻量：

- 只放在 `已入池` 区域
- 默认折叠
- 展开后提供：
  - handle
  - 显示名
  - 标签
  - 粉丝量级
  - 备注

提交动作：

- `加入账号池`
- `清空`

---

## 4. 本轮不做的内容

为了避免再次扩散，这一轮明确不做：

- 新增新的主标签
- 重新扩展搜索模板体系
- 重做悬浮窗大结构
- 重做 popup 大结构
- 新增复杂内容分析页

本轮只处理：

- 内容识别
- 执行强度区交互
- 账号工作台批量与默认模式重构
- 手动新增账号回补

---

## 5. 实施顺序

建议顺序：

1. 先修内容识别
2. 再修执行强度与每日数量
3. 再重构账号工作台模式
4. 最后补回手动新增账号

原因：

- 内容识别问题最影响信任
- 执行强度是高频核心交互
- 账号工作台是结构问题，需要在前两者稳定后再整体收

---

## 6. 验收标准

### 6.1 内容识别

- 发普通短推后，计入短内容
- 只有 `Article` 被计入长文
- 线程仍能单独计数

### 6.2 执行强度

- 点击 `保守 / 标准 / 强执行`，输入框数字立刻变化
- 修改输入框后，状态切成 `自定义`
- 改完后能自动保存
- 保存后今天目标同步更新，但已完成进度保留

### 6.3 账号工作台

- 默认模式下不显示复选框
- 进入批量模式后才显示复选框和批量条
- 支持 `全选当前页`
- 支持 `全选当前筛选结果`
- 卡片标签仍然可以直接改单条分类

### 6.4 手动新增账号

- `已入池` 区域能展开手动新增
- 提交后账号成功进入正式账号池

---

## 7. 默认实施策略

如果进入开发，本轮采用以下默认策略：

1. 长文只认 `Article`
2. 其他原创默认按短内容回退
3. 批量模式保留，但默认关闭
4. 手动新增账号保留并放回工作台下方
5. 自动保存采用温和策略，不做每次输入即保存
