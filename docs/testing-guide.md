# Testing Guide

更新日期：2026-05-15

## 1. Phase 3 本地加载

### 1.1 先构建扩展

在仓库根目录运行：

```powershell
npm run build:extension
```

构建成功后，扩展输出目录是：

```text
dist/extension
```

### 1.2 在 Chrome 里加载

1. 打开 `chrome://extensions/`
2. 打开右上角“开发者模式”
3. 点击“加载已解压的扩展程序”
4. 选择目录 `dist/extension`

### 1.3 Phase 3 需要验证的结果

加载完成后，至少检查下面几项：

1. 扩展图标可以点击
2. `popup` 可以正常打开
3. 点击 `popup` 里的“打开设置”可以进入 `options`
4. `options` 页面保存设置后，重新打开仍然保留
5. 打开 `https://x.com/home` 后，再打开 `popup`，能看到页面已连接
6. 页面 DOM 中存在 `#x-growth-task-coach-root`

## 2. 当前阶段只验证什么

`Phase 4` 在 `Phase 3` 的基础上，开始验证今日任务系统。

当前重点检查：

- 打开插件后能生成今天任务
- 可以手动点 `+ / -` 调整任务进度
- 完成率会立刻更新
- 点“重置今天”后，任务进度会归零
- 连续天数和近 7 天稳定度可以正常显示

## 3. Phase 5 需要额外验证的结果

`Phase 5` 开始尝试自动记录你已经手动完成的发帖动作。

建议这样验证：

1. 打开 `x.com`
2. 保持扩展 `popup` 打开或发完后再打开
3. 手动发布一条原创帖，确认“原创帖”自动 `+1`
4. 手动回复一条帖子，确认“高质量回复”自动 `+1`
5. 手动做一次引用转发，确认“引用转发”自动 `+1`
6. 如果自动识别没有成功，手动点 `+` 仍然可用

说明：

- 当前阶段仍然不做自动发帖
- 当前阶段只记录用户已经手动完成的动作
- 自动识别优先走保守策略，不追求 100% 命中

当前仍不要求：

- 粉丝快照读取
- 账号池
- 搜索模板
- 复盘生成

这些属于后续阶段。

## 4. Phase 6 需要额外验证的结果

`Phase 6` 开始把“结果”和“对象”接进插件：

- 粉丝快照
- 账号池
- 基于账号池分类的半自动互动记账

建议这样验证：

1. 去 `options` 页填写自己的 `X handle`
2. 在自己的主页打开 `x.com/<your-handle>`，确认 `popup` 里出现粉丝快照
3. 在 `options` 页往账号池至少添加：
   - `1` 个大 V
   - `1` 个同生态账号
4. 手动回复账号池里的大 V，确认：
   - “高质量回复”自动 `+1`
   - “大 V 互动”也自动 `+1`
5. 手动引用账号池里的同生态账号，确认：
   - “引用转发”自动 `+1`
   - “同生态互动”也自动 `+1`
6. 回到 `popup`，确认“今日建议互动”里能看到账号池推荐结果

说明：

- 当前仍然不自动判断谁是大 V、谁是同生态
- 这两个定义先由你在账号池里手动标记
- 插件只负责利用这个标记做半自动记账

## 5. Phase 7 需要额外验证的结果

`Phase 7` 开始把搜索入口、每日复盘、内容形态任务和候选账号导入接进插件：

- 固定搜索模板
- 每日复盘草稿
- 内容形态识别
- 分阶段内容任务
- Following / Followers 候选账号采集
- 标签建议
- 批量导入账号池

建议这样验证：

1. 去 `options` 页确认默认搜索模板已经出现，至少能看到：
   - `问题帖入口`
   - `热门构建帖`
2. 在 `popup` 里确认内容任务已经按当前阶段变化：
   - `0-100` / `100-1000`：`短内容输出`、`长文`
   - `1000-5000`：`短推`、`线程`、`长文`
3. 手动发一条普通短推，确认：
   - 内容识别区域有更新
   - 相应内容任务自动加数
4. 如果你能发线程或长文，再分别确认：
   - 线程会落到 `线程` 或 `短内容输出`
   - 长文会落到 `长文`
5. 打开你自己的 `Following` 或 `Followers` 页面，向下滚动一段
6. 回到 `options` 页，确认“账号工作台”里开始出现待处理账号
7. 检查账号卡片是否已经把这些信息放在用户名下面并排展示：
   - `角色标签`
   - `影响力标签`
   - `处理状态`
8. 试一下工作台筛选：
   - `待处理 / 已入池 / 已忽略`
   - `同生态 / 对标学习 / 选题来源`
   - `0-500 / 500-1k / 1k-5k / 5k-10k / 10k-20k / 20k+`
9. 试一下批量处理：
   - `全选当前可操作项`
   - `仅勾选同生态`
   - `仅勾选对标学习`
   - `仅勾选选题来源`
   - `按建议导入`
   - `批量标记为同生态`
   - `批量标记为对标学习`
   - `批量标记为选题来源`
10. 切到 `已入池`，确认刚导入的账号可以继续：
   - `编辑`
   - `打回待处理`
   - `标记忽略`
11. 回到 `popup`，确认“今日建议互动”里能看到刚导入的账号，并且推荐文案里会显示：
   - 角色标签
   - 影响力标签
12. 在 `popup` 的“每日复盘”区域填写：
   - 今日最佳帖子 URL
   - 今日最佳回复 URL
   - 最佳帖子形态
13. 点击“保存链接”，再关闭并重新打开 `popup`，确认这些信息仍然保留
14. 点击“复制草稿”，确认可以得到一段当天复盘文案

说明：

- 当前候选导入是“被动采集”，不是后台全量扫描
- 只有你主动打开并滚动出来的账号，插件才会收进候选池
- 角色标签只是建议，不是最终真值
- 影响力标签只代表粉丝量级，不代表账号用途
- 最终是否导入账号池、导入成哪类，仍然由你确认
- 如果某次原创内容未能完整识别，系统会先按更保守的内容任务兜底计入

## 6. Phase 7.5 需要额外验证的结果

`Phase 7.5` 重点不是再加一大堆新模块，而是把使用体验打磨顺：

- X 页面悬浮轻面板
- 执行强度即时生效
- 自定义人设叠加
- 中文搜索模板
- 三页化账号工作台

建议这样验证：

1. 去 `options` 页，确认顶部已经拆成 3 个工作区：
   - `执行设置`
   - `候选处理`
   - `正式账号池`
2. 在 `执行设置` 里确认执行强度已经收成一个统一面板：
   - `保守`
   - `标准`
   - `强执行`
   - `自定义`
3. 先切 `保守 / 标准 / 强执行`，确认下面的任务目标会跟着变
4. 再试着改一项可调目标，例如：
   - `高质量回复`
   - `选题收集`
5. 确认你一旦手动改数量，当前模式会变成 `自定义`
6. 点击 `保存并重建今天任务`
7. 再打开 `popup`，确认：
   - 今天的目标值已经变化
   - 之前已经完成的进度没有被清零
8. 在 `执行设置` 里勾选至少一个内置人设叠加
9. 再自己新建一个自定义人设，至少填写：
   - 名称
   - 关键词
   - 选题提示
   - 表达规则
10. 保存设置后，确认：
   - 中文搜索模板的描述和查询语句会跟着当前人设变化
   - `popup` 里会出现“今日内容建议”
   - 每日复盘建议会比之前更贴近你的人设
11. 再点一次：
   - `按当前人设重建系统模板`
   - `恢复系统模板`
   确认模板列表会刷新成中文版本
12. 打开 `x.com/home` 或任意 `x.com/<handle>` 页面，确认右上角出现悬浮轻面板
13. 在悬浮轻面板里确认：
   - 能看到今天完成率
   - 能看到少量核心任务
   - 可以直接点 `+ / -`
   - 可以点 `收起 / 展开`
14. 去 `候选处理` 页，确认顶部有明确提醒：
   - 只有打开 `Following / Followers` 并滚动后才会更新
15. 在 `候选处理` 页试这些操作：
   - 搜索
   - 来源筛选
   - 建议标签筛选
   - `全选当前页 / 仅勾某一类 / 清空勾选`
   - 直接在卡片上改角色标签
   - 勾选后再批量加入正式账号池
   - 批量忽略
16. 去 `正式账号池` 页，确认：
   - 可以搜索
   - 可以按角色标签筛选
   - 可以按粉丝量级筛选
   - 可以直接在卡片上改角色标签
   - 可以直接在卡片上改粉丝量级
   - 勾选后才出现批量打回待处理 / 批量移到已忽略 / 批量删除
17. 观察账号卡片正面是否已经变短：
   - 用户名
   - 角色标签
   - 粉丝量级标签
   - 简短 bio / 备注

说明：

- `执行强度` 现在会在保存后立即重建今天任务目标，但会尽量保留你今天已经完成的数量
- `Following / Followers` 仍然不是后台全量扫描，而是你主动打开并滚动时才更新
- `悬浮轻面板` 是轻量执行入口，详细信息仍然以 `popup` 为主
