# Phase 7.10 账号工作台与复盘推文化优化方案

更新日期：2026-05-16

## 1. 这轮评估做了什么

这轮不是继续直接开发，而是先重新检查当前界面是否已经适合进入下一步实施。

本次评估依据包括：

1. 当前账号工作台真实界面
2. 当前 `popup` 里的每日复盘区块
3. 当前设置页与工作台实现代码
4. 前面已经确定的设计基线
   - `Linear`
   - `Raycast`
   - `GitHub Issues`

这轮重点判断两件事：

1. 账号工作台的新结构现在是否已经足够合理
2. `popup` 里的每日复盘是否真的适合“复制后直接发推”

---

## 2. 总结结论

### 2.1 账号工作台

方向是对的，但当前实施计划还需要再收一次结构。

核心问题不是功能缺失，而是：

- 工具条层级还不够清楚
- 批量模式还不够“状态化”
- 手动添加账号的位置还不够稳定
- 待处理与已入池虽然已经接近统一，但仍然像两套列表

### 2.2 popup 每日复盘

现在的每日复盘**方向是对的**，但**还不是一条适合直接发的推文草稿**。

当前问题主要有：

- 口吻太像系统总结
- 句子太密
- 预览像说明，不像内容
- 链接字段对复制结果的价值兑现还不够清楚

所以这轮不建议删掉每日复盘，而是建议把它改成：

> **可以直接复制出去发的“今日复盘推文草稿”**

---

## 3. 账号工作台：产品评估

## 3.1 当前方案里合理的部分

下面这些方向已经可以保留：

1. 继续保留统一账号工作台
2. 继续保留全局搜索
3. 继续保留批量模式，但默认关闭
4. 继续保留标签贴着账号名直接改
5. 继续保留 `待处理 / 已入池 / 已忽略`

这些方向都没有问题。

## 3.2 当前方案里还不够合理的部分

### A. 工具条层级还是不够稳

如果把下面这些都放在同一层：

- `待处理 / 已入池 / 已忽略`
- 搜索框
- 来源筛选
- 标签筛选
- 粉丝量级筛选
- 批量模式
- 手动添加账号

那界面会显得很满，而且很像“把功能全塞在一起”。

从产品层级上看，它们至少分成三类：

1. **视图切换**
   - `待处理 / 已入池 / 已忽略`

2. **主入口**
   - 搜索框

3. **辅助筛选**
   - 来源 / 标签 / 粉丝量级

4. **模式 / 全局动作**
   - 批量处理
   - 手动添加账号

所以这轮不建议“完全合并成一行”，而是要做成**两层工具条**。

### B. 批量模式应该更像“进入一种状态”

现在如果只是一个普通按钮，用户会把它理解成一次动作，而不是一种工作模式。

更合理的理解应该是：

- 默认：单条直改
- 点击 `批量处理`：进入批量状态
- 批量状态下：
  - 才显示复选框
  - 才出现批量条
  - 工具条视觉也要有状态变化

### C. 手动添加账号不能再埋在 `已入池` 视图内部

这个入口从语义上看是**全局动作**，不是“已入池列表的一部分”。

如果继续放在 `已入池` 里面，会有两个问题：

1. 用户以为它只属于 `已入池`
2. 编辑账号时，表单位置不稳定，用户需要找

所以它应该挪成**全局入口**。

## 4. 账号工作台：设计评估

## 4.1 当前主要视觉问题

### A. 行与行之间的“语法”不统一

当前容易出现：

- 第一行是状态切换
- 第二行是搜索和筛选
- 第三行是批量模式
- 第四行又冒出手动表单

这样每一层都像“主层”，就会乱。

### B. 待处理和已入池卡片还是不够像同一个系统

虽然现在已经比之前统一很多，但仍然存在这种感觉：

- 候选卡片更像内容卡
- 已入池卡片更像管理卡

这说明后面要继续统一字段顺序和操作位置。

### C. 右侧动作还是偏重

账号卡片上的动作，后面应该继续朝“轻菜单”方向靠，而不是排一串重按钮。

## 5. 账号工作台：修正版结构方案

## 5.1 顶部主工具条

建议固定为这一层：

### 左侧

- `待处理 / 已入池 / 已忽略`

### 中间

- 全局搜索框

### 右侧

- `批量处理`
- `手动添加账号`

### 说明

- 这一层只允许放视图切换、主入口和全局动作
- 不再往这一层塞筛选器

## 5.2 第二层筛选条

这一层只放筛选器：

- 全部来源
- 全部标签
- 全部粉丝量级
- 清空筛选

### 说明

- 筛选器永远是辅助层
- 不和状态切换抢主层级

## 5.3 批量模式展开方式

建议：

- 默认隐藏
- 点击 `批量处理` 后才进入

进入后：

1. 卡片左侧显示复选框
2. 工具条下方出现批量条
3. 批量条只放：
   - 已选 N 个
   - 全选当前页
   - 全选筛选结果
   - 清空
   - 加入账号池
   - 设为同生态
   - 设为对标学习
   - 忽略 / 恢复
   - 退出批量

### 说明

- 批量条不再单独占大块空间
- 只在批量模式下出现
- 普通模式下完全消失

## 5.4 手动添加账号

建议改成：

- 顶部右侧全局入口
- 点击后打开轻量弹层或抽屉
- 新增和编辑复用同一套表单

### 这样更合理的原因

1. 这是低频动作，不该常驻列表内部
2. 编辑时能直接复用，不用跳回某个视图里找表单

## 5.5 卡片统一规则

待处理 / 已入池 / 已忽略 全部按同一骨架展示：

1. 用户名 + 主标签
2. handle
3. bio
4. 具体粉丝数 + 量级标签
5. 来源 / 最近互动 / 次信息
6. 轻量操作

### 明确删掉

- “更适合作为对标对象”
- “量级明显更高”
- 冗余建议文案

这些对判断和操作帮助太小，应该删掉。

## 6. popup 每日复盘：产品评估

## 6.1 这块有没有保留必要

**有必要，而且应该保留。**

原因不是“它看起来完整”，而是它天然适合承担一个很有价值的动作：

> **把你今天的执行结果沉淀成一条可分享的复盘推文**

这件事和插件的目标是高度一致的：

- 你做了任务
- 你有内容产出
- 你需要复盘
- 你也可以顺手把复盘公开发出来

所以每日复盘不该删。

## 6.2 当前为什么还不够好

当前版本更像：

- 内部日报
- 系统总结
- 任务面板的结果说明

而不是：

- 一条用户愿意直接发出去的推文草稿

具体问题：

1. 第一眼看上去像说明块，不像内容块
2. 句子太密，读起来累
3. 太多“系统口吻”
4. 没有明显的推文结构感
5. 链接补充虽然存在，但对复制后的结果帮助不够直接

---

## 7. popup 每日复盘：修正版方案

## 7.1 新定位

后面这块要明确成：

> **今日复盘推文草稿**

不是“系统总结”，也不是“内部日志”。

## 7.2 首屏结构

首屏只保留四层：

1. 标题
   - `今日复盘推文草稿`

2. 一段可直接发的推文预览
   - 3 到 5 行
   - 自然断句
   - 不是一整段压在一起

3. 一行轻量统计
   - `短推 X · 线程 Y · 长文 Z`

4. 两个动作
   - `复制复盘`
   - `重置今天`

## 7.3 折叠区

把这些内容统一放进折叠区：

- 最佳帖子 URL
- 最佳回复 URL
- 最佳内容形态

折叠区标题建议改成：

- `附上今天表现最好的链接（可选）`

比现在的“补充素材”更直白。

## 7.4 推文草稿写法

当前不建议继续用这种系统句式：

- `今天完成率 58%。`
- `最值得继续的是……`
- `还剩 4 项没完成。`

建议改成更适合直接发的结构：

### 结构模板

第一行：今天整体结果  
第二行：今天内容产出  
第三行：今天最有效动作  
第四行：明天重点

### 示例风格

`今天打卡：完成率 58%，粉丝持平。`
`产出：短推 0 / 线程 0 / 长文 8。`
`今天最有效的是：大 V 互动，另外完成了 22 次真实互动。`
`明天先补「选题收集」，继续把节奏做稳。`

如果补了最佳帖子或最佳回复链接，再附在最后。

### 文案原则

- 更像人会发的话
- 更适合复制后直接贴到 X
- 保留复盘感，但不要像机器总结

## 8. 最终修正版实施建议

## 8.1 工作台部分

### 保留

- 统一工作台
- 全局搜索
- 批量模式
- 标签直改

### 调整

1. 工具条拆成两层
2. 批量模式改成模式切换
3. 手动添加账号改成全局入口
4. 卡片结构彻底统一

## 8.2 popup 复盘部分

### 保留

- 每日复盘
- 复制复盘
- 重置今天
- 链接补充

### 调整

1. 标题改成“复盘推文草稿”
2. 首屏改成推文预览
3. 文案改成适合直接发的结构
4. 详细链接全部收进折叠区

## 9. 我的最终判断

如果你让我用一句话收口：

**这轮的关键不是继续加功能，而是把账号工作台做成真正统一的工作台，把每日复盘做成真正能发的复盘推文。**

这两件事做好之后，后面的细修才值得继续做。
